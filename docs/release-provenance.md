# Governed release provenance

SpruceGoose release artifacts use two closed, canonical JSON objects. The embedded `spruce-goose-release-provenance-v1` member records exact source commit/tree/dirty state, explicit UTC build time, builder, governed task and transaction, actual Elixir/Erlang/Mix versions, and every tracked migration in strict path order with SHA-256 plus a digest of the ordered set. The portable `spruce-goose-release-receipt-v2` binds the final archive basename, SHA-256, byte size, source commit and tree, full OTP and Elixir versions, build timestamp, migration-set digest, and embedded provenance SHA-256. Missing, extra, duplicate, unordered, malformed, or noncanonical representations fail closed.

`inspect-governed-release ARCHIVE` reads gzip or xz tar bytes without extracting candidate files or starting the release, application, or Repo. Exactly one `releases/<dynamic-version>/governed-provenance.json` member is required; no application version is hardcoded. `validate-governed-release` validates the canonical receipt, archive name/digest/size, unique embedded member and digest/schema, all repeated receipt fields, dirty policy, expected commit/tree, then the exact canonical destination migration inventory. Destination-looking paths are never accepted as mutation targets.

Destination inventory is required by default. `--artifact-only` is an explicit weaker evidence mode and prints `mode=artifact-only`; it proves artifact self-consistency only, not destination readiness. `--allow-dirty` accepts only explicitly classified `non-transferable-dirty-evidence`; it never makes an artifact clean or transferable.

`build-governed-release` rejects dirty source before output creation or Mix invocation. Dirty exercise requires both `SPRUCE_GOOSE_ALLOW_DIRTY_EVIDENCE=1` and a pre-existing `SPRUCE_GOOSE_DIRTY_EVIDENCE` file. Builder, governed task/transaction, UTC time, output directory, and `SOURCE_DATE_EPOCH` are explicit inputs. The output directory must be external to the canonical repository root; equal, direct/nested, relative, lexical traversal, symlink-parent, and nonexistent-tail paths that resolve inside the repository are rejected before creation or tool invocation. Resolution walks to the nearest existing ancestor and follows its real path before appending the absent tail. Output construction occurs under an invocation-private, same-parent directory with `umask 077`; directories are owner-only `0700` and created archive/receipt files are `0600`. Publication is a verified no-replace rename to the exact requested path. Automatic recursive pathname cleanup is never attempted because a same-identity process can replace a checked pathname before deletion.

Mix project identity is read only after warnings-as-errors compilation using `mix run --no-start --no-compile`. The builder uses one exact-identity check for HEAD commit, HEAD tree, and complete tracked/untracked status: it runs after release assembly and again immediately after receipt writing, before marking success or publishing any archive, receipt, or clean-source classification. Drift is classified as `source changed during build`, publication is refused, and the builder exits with status 2. On every failure after private creation, stderr records `published=false`, `automatic-cleanup-attempted=false`, the requested final path and its point-in-time state, creation-time private device/inode, last-known private path, current path state/identity when observable, and `owned-private-location=UNKNOWN` after absence or replacement. A `same-object` observation says only that the last-known path currently references the recorded object; it does not guarantee future custody. The external output therefore cannot dirty or otherwise influence the source-state decision.

The owner-only work tree is deliberately retained as `retained-work-residue`, with published outcome plus governed task/transaction run identity. It is not normal cleanup: operators must use bounded governed cleanup under an external quota/monitoring policy and must not infer deletion authority from the reported pathname. Archive order, timestamps, ownership, xz threading/check mode, and modes are normalized. The builder refuses an archive larger than 64 MiB. GNU tar receives the sorted release top-level names rather than `.`, so members use one canonical representation without a leading `./`. The validator accepts exactly `releases/<dynamic-version>/governed-provenance.json` and rejects leading-dot, traversal, prefixed, duplicate, or canonical-plus-alternative ambiguity fail-closed.

## Activation and rollback

`deploy-sprucegoose` and `rollback-sprucegoose` are host-local wrappers. Both require an archive, its receipt, the expected commit and tree, an exact destination migration inventory, an install path, an activation-record path, and a governing task. They reject a dirty worktree, missing receipt, receipt or provenance mismatch, and migration drift before staging or service control.

The release cookie is normalized at build time: `mix release` mints a fresh random `releases/COOKIE` on every build, which both breaks byte-identical double builds and ships a runtime credential inside a transferable artifact. `build-governed-release` therefore overwrites the member with the fixed placeholder `GOVERNED-PLACEHOLDER-COOKIE-PROVISION-AT-ACTIVATION` before archiving. Activation refuses a staged release whose cookie is anything but that placeholder, then provisions the real value on the destination: the previous install's cookie when one exists, otherwise a freshly generated one, owner-only `0600`. Archives therefore never carry a live cookie.

The default is a validation-only dry run. A real activation additionally requires `--activate --confirm-activation ACTIVATE:<target>:<task>`. The script extracts to an owner-only sibling directory, checks for the release executable, moves the prior release into a task-named rollback slot, installs the staged release, writes a canonical activation record, and restarts `sprucegoose.service`. If restart fails, it moves the failed release aside, restores the prior directory, and attempts to restart the prior service. Rollback requires a reason and an existing prior activation record, then applies the same artifact and migration-parity gates to the selected rollback archive. These scripts do not transfer artifacts, discover destination state, run migrations, or bypass operator approval.

## Evidence classes

* **Source/static PASS:** formatter, standalone compilation, unit/script regressions on exact bytes.
* **Boot-free behavioral PASS:** canonical codecs, in-memory archive inspection, CLI/parser, receipt/validator, and no-write accounting.
* **Dirty build exercise:** always non-transferable evidence, even if repeated bytes match.
* **Transferable clean release:** requires a clean committed candidate built twice with identical declared inputs, byte-identical archives and receipts, and successful full validation against destination inventory.
* **UNEXECUTED:** dependency/setup prevented execution; it is neither PASS nor implementation FAIL.

Production integration, destination inventory capture, application/Repo/runtime boot, DB migration, service activation, transfer, and authority mutation remain **UNEXECUTED** for this implementation task. Dry-run validation and disposable local staging tests do not authorize production activation. Any workspace write not explicitly intended—including `erl_crash.dump`—invalidates read-only evidence; before/after inventories must reject it.
